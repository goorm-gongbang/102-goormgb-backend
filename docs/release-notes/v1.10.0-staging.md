> **배포 환경**: staging
> **이전 버전**: v1.9.0-staging
> **배포 브랜치**: dev → staging
> **배포 담당자**: @Seulgi

## 주요 변경 사항

API Gateway 쓰기 메서드 인증 우회 차단 + Thread Pool DoS 대응(보안), 결제 수단별 예매 완료 메일 입금 안내 분기, 내 주문 이외 요청에 대한 권한 에러를 404로 통합, Hold 단계 주문당 8매 사전검증 제거 + 결제 완료(SOLD) 좌석이 재Hold 시 풀리는 데이터 정합성 버그 수정, staging 에러 응답의 주요 도메인 코드/메시지 passthrough 추가

## 기획/클라우드팀 참고 사항

- **API 응답 변경 (프론트 협의 필요)**:
  - 마이페이지/결제 API에서 내 주문이 아닌 자원 요청 시 응답이 **403 → 404 로 변경**됨. 프론트의 분기 처리 확인 필요.
  - staging 환경의 일부 도메인 에러 코드(`EXCEEDED_MAX_TICKETS_PER_ORDER`, `SEAT_ALREADY_HELD_BY_OTHER`, `SEAT_ALREADY_SOLD`, `SEAT_LOCK_ACQUISITION_FAILED`, `NO_CONSECUTIVE_SEAT_AVAILABLE`, `QUEUE_ALREADY_ENTERED`, `ADMISSION_TOKEN_EXPIRED` 등 22개)가 응답 `code` 필드에 enum 이름 그대로 내려감. 프론트가 에러 분기(재시도/안내 문구/결제 흐름 전환 등)에 활용 가능.
- **보안 강화**:
  - API Gateway 가 인증되지 않은 쓰기 메서드(POST/PUT/PATCH/DELETE) 요청을 게이트 단계에서 차단.
  - Tomcat thread pool 상한이 설정되어 무제한 스레드 점유 DoS 차단.
- **데이터 정합성 개선**:
  - 동일 유저가 같은 경기에 결제 완료 후 다른 좌석을 재Hold 하는 흐름에서 발생하던 `match_seat.sale_status` 비정합 버그 해소. 추천/일반 좌석 조회의 잘못된 후보 재선택 문제 해소.
- **정책 변경**:
  - Hold 단계 주문당 8매 검증이 서버에서 제거됨. 8매 제한은 프론트엔드 + Order-Core `createOrder` 가 담당. URL 우회 시도는 Order-Core 에서 최종 차단되며, 별도 rate limit / 인프라 보호로 Hold DoS 는 별개 계층에서 방어.
- **DB 마이그레이션**: 없음
- **환경변수 변경**: Tomcat thread pool 관련 application.yaml 변경만 있음 (별도 `.env` 추가 없음)
