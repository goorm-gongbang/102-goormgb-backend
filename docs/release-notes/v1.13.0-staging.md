## 주요 변경 사항

- **Phase 3 API 응답 Redis 캐시 도입**: 자주 폴링되는 `GET /matches?date=` (30s TTL) 와 `GET /matches/{matchId}/seat-groups` (5s TTL) 응답을 Redis 분산 캐시로 흡수해 DB·JVM 조립 비용 제거.
- **Phase 4 커넥션 회전율·스레드 점유 시간 단축**: Queue `open-in-view=false`, BookingOptions prequeue 마커 retry 를 Resilience4j 기반으로 전환해 Thread.sleep 제거, 대기열 진입 Redis 왕복 3회 → 1회 통합 — 1000+ VU 부하에서의 커넥션/스레드 풀 고갈 병목 해소.
- **Redis 캐시 역직렬화 핫픽스**: `DefaultTyping.NON_FINAL` + Java record(final) 조합에서 `@class` 힌트 누락으로 발생하던 `/auth/me` 등 500 에러 (`missing type id property '@class'`) 를 `EVERYTHING` 전환으로 복구.
- **인프라 파라미터 환경변수화**: Tomcat 스레드 / HikariCP 풀 파라미터를 `${ENV:default}` 로 전환해 부하테스트 / 프로파일별 튜닝이 배포 재빌드 없이 가능.

## 기획/클라우드팀 참고 사항

### 환경변수 (신규 — override 시 적용)
배포 시 기본값 유지하면 기존 동작과 동일. 부하테스트 / 튜닝 목적으로 `Deployment.env` 에서 override 가능.

| 변수 | 기본값 | 적용 서비스 |
|------|--------|-------------|
| `SERVER_TOMCAT_THREADS_MAX` | 200 | auth-guard, order-core, queue, seat |
| `SERVER_TOMCAT_THREADS_MIN_SPARE` | 10 | 동일 |
| `DB_POOL_MAX` | 20 | 동일 |
| `DB_POOL_MIN_IDLE` | 5 | 동일 |

> Seat/Queue 는 부하테스트 시 `SERVER_TOMCAT_THREADS_MAX=400`, `DB_POOL_MAX=30` 등 상향 운영을 권장 — 인프라팀 별도 협의 항목.

### 배포 직후 Redis 키 정리 (필수)
DefaultTyping 포맷이 `NON_FINAL` → `EVERYTHING` 으로 바뀌어 **구 포맷 엔트리는 새 reader 에서 500** 을 냅니다. 배포 완료 직후 아래 패턴을 DEL 해주세요. TTL(최대 10분) 만료까지 기다려도 되나 간헐적 500 이 노출됩니다.

```bash
redis-cli --scan --pattern 'user-by-id::*' | xargs -r redis-cli DEL
redis-cli --scan --pattern 'auth-me::*' | xargs -r redis-cli DEL
redis-cli --scan --pattern 'matches-list-response::*' | xargs -r redis-cli DEL
redis-cli --scan --pattern 'seat-groups-response::*' | xargs -r redis-cli DEL
```

bastion 에 `redis-cli` 가 없을 경우 `sudo apt install redis-tools` 또는 Redis Pod 에 `kubectl exec` 로 진입해 실행.
